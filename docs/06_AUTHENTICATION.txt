VAYRO — 06_AUTHENTICATION.txt
================================
كل ما هو موثّق هنا مُنفَّذ فعليًا في apps/api/src/modules/auth/.

────────────────────────────────────────
Endpoints (مسبوقة بـ /api/v1)
────────────────────────────────────────
POST /auth/register            — عام. ينشئ حسابًا بحالة PENDING + دور USER افتراضي.
POST /auth/login                — عام. Rate limit: 5/دقيقة/IP. يعيد accessToken +
                                   يضبط refresh token كـ HttpOnly cookie.
POST /auth/refresh              — عام. يقرأ الكوكي، يُدوّر refresh token، يعيد
                                   accessToken جديدًا.
POST /auth/logout               — محمي (JWT). يُبطل الجلسة الحالية ويمسح الكوكي.
POST /auth/password/forgot       — عام. Rate limit: 3/دقيقة/IP. رد موحّد دائمًا.
POST /auth/password/reset        — عام. token لمرة واحدة، ينتهي خلال 30 دقيقة.

────────────────────────────────────────
تدفق التسجيل (Register)
────────────────────────────────────────
1. التحقق من صيغة username عبر UsernamePolicy (a-z0-9_، 3-20 حرفًا).
2. رفض إن كان في reserved_usernames.
3. رفض إن كان username/email/phone مستخدمًا مسبقًا (رسائل خطأ مختلفة هنا لأن
   الهدف تجربة تسجيل واضحة — على عكس تسجيل الدخول حيث الرسائل عامة عمدًا).
4. Argon2id hash لكلمة المرور.
5. إنشاء User + UserProfile فارغ + ربط دور USER — كل ذلك دون لمس Wallet/Ledger
   (تلك مسؤولية Wallet module في Phase 3، ليس Auth).

────────────────────────────────────────
تدفق الدخول (Login)
────────────────────────────────────────
1. بحث بالبريد أو username (case-insensitive عبر username_lower).
2. رفض عام INVALID_CREDENTIALS إن لم يوجد الحساب.
3. رفض ACCOUNT_LOCKED إن كان locked_until في المستقبل.
4. رفض ACCOUNT_UNAVAILABLE إن كانت الحالة BANNED/FROZEN.
5. التحقق من كلمة المرور عبر argon2.verify.
6. عند الفشل: زيادة failed_login_count، وقفل الحساب 15 دقيقة بعد 5 محاولات.
7. عند النجاح: تصفير العداد، توليد accessToken (JWT) + جلسة جديدة (refresh token).

────────────────────────────────────────
Access Token (JWT)
────────────────────────────────────────
- Payload: { sub: public_id, username, roles[], permissions[] }.
- لا يحمل الـ id الداخلي أبدًا.
- صلاحية قصيرة (افتراضي 15m، JWT_ACCESS_TTL في .env).
- التحقق: JwtStrategy (passport-jwt) + JwtAuthGuard (عام على كل Route، @Public() للاستثناء).

────────────────────────────────────────
Refresh Token & Rotation
────────────────────────────────────────
- 64 بايت عشوائي (crypto.randomBytes) — لا JWT، توكن عشوائي بسيط يُخزَّن كـ hash فقط.
- عند /auth/refresh: TokensService.rotate() يبحث عن الجلسة بمطابقة الـ hash:
    - غير موجودة → INVALID_REFRESH_TOKEN.
    - موجودة لكن revoked_at ليس فارغًا → REFRESH_TOKEN_REPLAY: تُبطَل فورًا
      كل جلسات المستخدم النشطة (دفاع ضد سرقة توكن مُستخدَم مسبقًا).
    - منتهية الصلاحية → REFRESH_TOKEN_EXPIRED.
    - صالحة → تُبطَل هذه الجلسة، تُنشأ جلسة جديدة (replaced_by_session_id يربطهما)،
      ويُعاد accessToken + refresh token جديدين.

────────────────────────────────────────
Sessions (الأجهزة)
────────────────────────────────────────
- GET /users/me/sessions: يعيد الجلسات النشطة للمستخدم الحالي فقط.
- DELETE /users/me/sessions/:id: يتحقق من الملكية (session.userId === caller.id)
  قبل الإبطال؛ 404 موحّد سواء لم توجد الجلسة أو لم تخصّ المستخدم.

────────────────────────────────────────
Password Reset
────────────────────────────────────────
- POST /auth/password/forgot: رد بنفس الشكل دائمًا (لا كشف لوجود الحساب).
  في NODE_ENV != production فقط، يُعاد devOnlyToken في الاستجابة الداخلية للخدمة
  (وليس عبر الـ Controller) لتسهيل الاختبار اليدوي المحلي — لا بريد فعلي يُرسَل بعد.
- POST /auth/password/reset: يتحقق من hash التوكن، usedAt، expiresAt، ثم يحدّث
  كلمة المرور ويُبطل كل الجلسات النشطة للمستخدم (دفاع ضد سرقة جلسة سابقة).

────────────────────────────────────────
2FA
────────────────────────────────────────
- الجدول (two_factor_secrets) والتشفير (EncryptionService) جاهزان.
- لا endpoint فعلي للتفعيل/التحقق من TOTP بعد في Phase 2 — سيُضاف عند الحاجة
  الفعلية إليه (تفعيل إجباري للـ Admin + طلبه قبل معاملات حساسة، Phase 3+).

────────────────────────────────────────
غير مُنفَّذ بعد (بصراحة)
────────────────────────────────────────
- التحقق الفعلي من البريد الإلكتروني/الهاتف (لا خدمة إرسال مربوطة).
- إرسال بريد إعادة تعيين كلمة المرور فعليًا (التوكن يُنشأ لكن لا يُرسَل عبر مزود بريد حقيقي).
- تفعيل 2FA من طرف المستخدم.
